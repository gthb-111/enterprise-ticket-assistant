# ServiceFlow AI 重构范围与验收标准

## 目标

将现有“企业工单分流 + 知识库问答助手”直接重构为面向真实业务闭环的
AI 应用：用户可以从企业文档获得带引用的答案；当问题无法可靠解决时，
Agent 可以查询或创建工单、识别高风险请求并转人工。

项目名称保持 `ServiceFlow AI`。重构在原项目目录内完成，通过 Git 历史
保留改造前的可恢复版本，不创建名称带 “2.0” 的平行项目。

## 目标用户与核心流程

主要用户是企业客服、运营人员和需要查询内部政策的一线员工。

```text
上传文档
  -> 解析与切分
  -> 建立关键词和向量索引
  -> 用户提问
  -> 查询改写与意图/风险判断
  -> 混合检索与 Rerank
  -> 有证据则流式生成带引用回答
  -> 证据不足或高风险则调用工单/转人工工具
  -> 记录会话、反馈、延迟和模型成本
```

## 本期范围

### 必须实现

- FastAPI 服务与 OpenAPI 文档。
- PDF、Markdown、TXT 文档上传、解析、切分和索引。
- 向量检索 + 关键词检索的混合召回。
- Rerank、查询改写、引用溯源和证据不足兜底。
- LangGraph Agent，至少提供知识检索、工单查询/创建、人工升级三类工具。
- Agent 状态、条件分支、最大步数、超时、重试和工具错误处理。
- 多轮会话、会话历史和流式回答。
- 工作台展示回答、引用、工具调用、进度和反馈。
- 可重复运行的评测脚本及结果页面。
- 单元测试、集成测试、Docker 启动方式和密钥配置示例。

### 暂不纳入

- 模型训练、微调或算法研究。
- 多租户、复杂 RBAC 和完整生产级权限系统。
- 为展示而引入但没有实际用途的消息队列或多个数据库。
- 多模态图片、语音和扫描件处理。
- 大规模高并发压测和生产 SLA。

## 目标架构

| 层 | 计划组件 | 职责 |
| --- | --- | --- |
| Web 工作台 | 现有前端重构 | 上传、对话、流式进度、引用和反馈 |
| API | FastAPI + Pydantic | 请求校验、SSE 流式接口、统一错误处理 |
| Agent | LangGraph | 路由、状态、工具调用和条件分支 |
| Retrieval | Embedding + 向量库 + BM25 + Rerank | 混合召回和相关性排序 |
| LLM | OpenAI 兼容适配器 | 模型调用、超时、重试、限流和成本统计 |
| Data | SQLite 起步，预留 PostgreSQL | 工单、会话、文档元数据和评测结果 |
| Cache | Redis，按实际需求启用 | 会话缓存或限流，不为了堆栈而使用 |
| Evaluation | 自定义评测脚本 | 检索、回答、工具、延迟和成本指标 |

实现时优先选择最容易稳定演示的方案，再通过适配器保留替换空间：

- 开发和小规模演示可以使用本地向量索引或 Qdrant 的轻量运行方式。
- 未配置模型密钥时仍能启动并演示文件解析、检索和确定性回退流程。
- 配置真实模型后启用生成式回答，但密钥只能从环境变量读取。
- 不把模型返回的文本直接当作业务决策，风险与工具边界仍由服务端控制。

## 评测设计

评测集计划扩展到 50 至 80 条，覆盖：

- 20 条以上可直接从文档回答的问题；
- 10 条以上需要改写或跨段落检索的问题；
- 10 条以上知识库没有答案的问题；
- 10 条以上高风险、权限边界或工具失败问题；
- 10 条多轮上下文问题。

至少对比以下方案：

1. 关键词检索基线；
2. 仅向量检索；
3. 混合检索；
4. 混合检索 + Rerank。

指标包括 Recall@K、MRR、引用覆盖率、答案有依据率、工具调用成功率、
P95 延迟和单次调用成本。所有展示数字必须由当前仓库中的评测脚本生成，
不允许手工编造。

## 验收标准

- 新环境按 README 步骤可以启动。
- 未配置 API Key 时仍可完成离线演示。
- 配置 API Key 后可以完成一轮真实的模型调用。
- 一次演示可以覆盖上传、问答、引用、Agent 工具调用和转人工。
- 评测脚本可从空数据开始重新生成结果。
- 核心业务逻辑有自动化测试，失败时有可读日志。
- README 包含架构图、运行方式、技术取舍、评测结果和已知限制。
- 项目负责人能够独立解释 RAG、Agent、流式接口和评测设计。

## 协作分工

我负责架构、基础工程、前端骨架、测试框架、排错、代码审查和文档收口。

你负责亲手完成并解释以下核心环节：

- 文档切分与索引数据设计；
- 混合检索和引用返回；
- 一个 Agent 路由与工具调用分支；
- 至少 10 条评测问题和结果分析。

每个阶段先说明原理，再实现最小版本，最后补测试和解释文档。遇到阻塞时
由我直接接手修复，但不会跳过对核心逻辑的讲解和复盘。

## 实施顺序

4. 加入查询改写、Rerank、引用和安全兜底。
5. 引入 LangGraph 与工单工具，补齐状态和错误处理。
6. 改造工作台，实现流式对话和 Agent 过程展示。
7. 扩充评测集，完成方案对比和指标页面。
8. 补 Docker、测试、演示录屏和面试问答。
