# 三分钟演示脚本

## 演示前检查

1. 使用项目虚拟环境启动服务：

   ```powershell
   .\.venv\Scripts\python.exe run.py serve
   ```

2. 打开 <http://127.0.0.1:8877>。
3. 确认页面左下角显示“deepseek-chat · 在线”。
4. 新建对话，保持右侧“轨迹”标签可见。

## 推荐流程

### 1. 介绍问题（20 秒）

“企业客服拿到问题后，不只是需要一个聊天框。系统还要判断业务类型、风险、
知识依据，以及什么时候必须转人工。这个项目把这些步骤做成一条可审计的
LangGraph 工作流。”

### 2. 普通知识问题（40 秒）

输入：

```text
支付宝退款通常多久到账？
```

展示：

- 答案逐 Token 出现；
- 答案里有可点击的引用编号；
- 右侧显示模型、延迟、Token；
- “依据”中可以看到命中的原文段落；
- “轨迹”中依次经过 prepare、knowledge_search、compose、persist_ticket。

讲解：

“模型只收到检索到的三段证据，不允许访问整个知识库。自动答复和建单由服务端
策略决定，模型不能绕过风险规则。”

### 3. 多轮追问（25 秒）

继续输入：

```text
那超过七天呢？
```

展示会话历史和 `memory_used` 对应的追问效果。

讲解：

“系统只对短问题或包含指代的追问拼接上一轮用户问题，避免每轮都携带全部历史
造成上下文噪声。”

### 4. 上传企业制度（40 秒）

点击“上传知识”，选择 `samples/travel_reimbursement.md`，分类选择“账单与支付”，
上传后提问：

```text
杭州地区网约车票据超过六十天还能报销吗？
```

展示答案来源变为 `upload://travel_reimbursement.md`。

### 5. 高风险分支（30 秒）

新建对话并输入：

```text
账号被盗，非本人刷卡消费，请马上冻结账号
```

展示 `P0`、`escalate`，轨迹最后进入 `human_handoff` 工具，而不是自动解决。

### 6. 评测收尾（20 秒）

点击右侧“评测”：

- 57 条内部回归问题；
- 分类准确率 100%；
- 优先级准确率 100%；
- 混合检索 Hit@3 为 100%；
- 对比四种检索方案。

说明：“这是同一批人工数据和规则调参后的内部回归，不代表线上泛化准确率；
下一步需要使用独立盲测集和真实工单。”

## 演示备用口径

- 如果模型网络失败：说明项目会自动回退到本地抽取式答案，然后再演示引用和
  Agent 轨迹。
- 如果 DeepSeek 额度不足：切换到 `SERVICEFLOW_LLM_ENABLED=0` 或清空 Key，
  项目仍能离线完成核心流程。
- 如果页面历史太多：点击“新建对话”，不要删除数据库。
