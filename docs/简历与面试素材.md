## STAR 讲法

### 问题

企业客服不只是需要一个聊天框。高风险问题、低置信回答和证据不足的问题如果被
自动回复，可能扩大损失。因此系统需要同时解决“能不能答”“依据是什么”和
“答不了该交给谁”。

### 方案

文档先解析、切分并持久化；查询经过业务词扩展和混合检索；Rerank 选择证据；
模型只能基于这些证据生成回答。服务端规则判断 P0-P3、自动答复阈值和人工交接；
LangGraph 把整个过程拆成可观察节点，并记录工具调用。

### 难点

1. 中文短查询容易误召回，因此保留关键词召回、覆盖率门槛和类目加权；
2. 离线哈希向量在本数据集上单独使用弱于 BM25，因此降低权重，不伪装成语义模型；
3. 模型可能编造，因此使用证据约束、引用返回、阈值门控和本地回退；
4. 流式输出需要同时展示 Agent 节点和模型 Token，因此使用 LangGraph custom stream
   加应用层 SSE。

### 结果与复盘

57 条内部回归问题中，意图分类和优先级均为 100%，混合检索 Hit@1 为 98.25%，
Hit@3 为 100%，没有优先级降级漏判。由于规则和评测数据一起调参，这些结果只能
证明回归通过，不能代表线上泛化。下一步应使用独立盲测集、真实脱敏工单和人工
标注的答案正确率。

## 高频追问

### 为什么用 LangGraph，而不是一个函数

流程有明确状态和分支，且需要展示节点和工具调用。LangGraph 便于测试条件路由、
追踪失败位置，也方便以后扩展更多工具。

### 模型为什么不能直接决定是否转人工

资金盗刷、账号安全和监管投诉需要稳定、可解释的业务策略。模型负责组织回答，
服务端规则负责权限和安全边界。

### 如何防幻觉

只发送检索证据；Prompt 禁止编造；返回 citations；证据不足不生成事实性答案；
服务端风险规则优先于模型文本。

### 如何实现流式

读取模型服务的 SSE delta，逐段通过 LangGraph custom stream 暴露，应用后端再以
浏览器可消费的 SSE 返回。答案完成后才写入会话和工单。

### 多轮记忆怎么控制

消息持久化到 SQLite；只有短问题或包含“那、这个、超过、怎么办”等指代时，才
拼接最近两轮用户问题，避免历史上下文污染独立问题。

### 项目不足

- 离线向量不是神经语义 Embedding；
- 评测集仍是人工合成数据，且参与调参；
- SQLite 不适合多实例高并发；
- 缺少正式登录、租户隔离和 RBAC；
- Docker 文件已提供，但开发机未安装 Docker，尚未完成容器实机验证；
- PDF 文本提取质量取决于原文件，没有 OCR。
